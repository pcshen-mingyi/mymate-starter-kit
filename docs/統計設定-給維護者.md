# 匿名計數：後端設定（給維護者）

目標：`install` +1、`uninstall` +1，用來判斷「要不要進一步訪談或發問卷」。
**不做使用者識別、不做行為分析。**

## 現況：已啟用

從 v2.0 起，端點已部署完成並填入 `_stats.mjs` 的 `STATS_ENDPOINT`，安裝與還原會各回報一筆。
後端是綁在統計試算表上的 Apps Script，授權範圍只有 `spreadsheets.currentonly`——**只能寫那一份試算表**。

**要整包關閉計數**：把 `_stats.mjs` 的 `STATS_ENDPOINT` 改回空字串 `""`，重新發版即可（留空＝完全不送出）。
**個別使用者要關閉**：設環境變數 `MYMATE_NO_STATS=1`，這是寫在 README 給使用者的方式。

下面是這套後端當初怎麼建起來的，供日後重建或換方案時參考。

---

## 選一個後端

需求很單純：一個能接 POST、把資料寫進某個地方的端點。常見選項：

| 選項 | 適合什麼情況 |
|---|---|
| Google Apps Script ＋ 試算表 | 不想新開服務、想直接在試算表看數字 |
| Cloudflare Worker ＋ KV／D1 | 想要純粹的計數端點、免費額度充足 |
| 既有的後端或資料庫 | 你們已經有現成的地方可放 |

下面以 Apps Script 為例，理由有二：步驟最少、不需要部署環境；
以及你們在 **TPM Dashboard 專案**已經用過 Apps Script，團隊熟悉，不必再學新工具。

> **注意**：這裡只是引用那邊的經驗當作選型參考。
> 本專案的統計**完全獨立**——請另建一份新的試算表與新的部署，
> 不會、也不應該動到 TPM Dashboard 的任何既有檔案或設定。

**換成其他方案也可以**——`_stats.mjs` 只在意「有一個能接 POST 的網址」。

---

## 步驟一：建一份**新的**試算表（不要沿用其他專案的）

1. 新開一份 Google 試算表，命名例如 `MYmate 小白包統計`。
2. 第一列填標題：

   | A | B | C | D |
   |---|---|---|---|
   | 時間 | 事件 | 版本 | 平台 |

## 步驟二：貼上 Apps Script

在該試算表：**擴充功能 → Apps Script**，貼上：

```javascript
var HEADERS = ["時間", "事件", "版本", "平台"];

function doPost(e) {
  try {
    var body = (e && e.postData && e.postData.contents) || "{}";
    var d = JSON.parse(body);

    // 只接受預期的值，其餘一律丟棄（公開端點會有爬蟲與雜訊）
    var event = d.event === "install" || d.event === "uninstall" ? d.event : null;
    if (!event) return ok();

    var version = String(d.version || "").slice(0, 20);
    var platform = String(d.platform || "").slice(0, 20);

    writeRow(sheet(), event, version, platform);
    return ok();
  } catch (err) {
    return ok(); // 解析失敗、寫入失敗——一律當作沒發生，仍回 200
  }
}

/** 用瀏覽器打開就能確認端點活著 */
function doGet() {
  return ContentService.createTextOutput(
    "MYmate starter kit stats endpoint (alive). POST {event, version, platform}."
  );
}

/** 資料分頁＝第一個分頁（不寫死名稱）。標題列不存在時補上。 */
function sheet() {
  var sh = SpreadsheetApp.getActiveSpreadsheet().getSheets()[0];
  if (sh.getLastRow() === 0) {
    sh.appendRow(HEADERS);
    sh.getRange(1, 1, 1, HEADERS.length).setFontWeight("bold");
    sh.setFrozenRows(1);
  }
  return sh;
}

/**
 * 寫一列。版本與平台一律以「文字」存。
 * 不這樣做的話，試算表會把 "2.0" 自動判成數字 2，
 * 之後 "2.10" 與 "2.1" 也會撞成同一個值，版本分布就不能用了。
 */
function writeRow(sh, event, version, platform) {
  var r = sh.getLastRow() + 1;
  var range = sh.getRange(r, 1, 1, 4);
  range.setNumberFormats([["yyyy/mm/dd hh:mm:ss", "@", "@", "@"]]);
  range.setValues([[new Date(), event, version, platform]]);
}

function ok() {
  return ContentService.createTextOutput("ok");
}
```

> 分頁用 `getSheets()[0]` 取第一個，不寫死名稱——改名也不會壞。
> 標題列會在第一筆資料進來時自動建立，不必先手動填。
> **版本欄一定要當文字存**（`writeRow` 在做的事）；用 `appendRow` 直接寫，`2.0` 會變成數字 `2`。

### 改了程式碼之後別忘記重新部署

`clasp push`（或編輯器存檔）只更新原始碼，**不會**更新已經在跑的網址。
既有部署固定在某個版本，要讓 `/exec` 換到新程式碼，得更新同一個部署（不是新建一個，
新建會產生新網址，`_stats.mjs` 裡的舊網址就會繼續跑舊程式碼）。

## 步驟三：部署

1. 右上「部署 → 新增部署作業」。
2. 類型選 **網頁應用程式**。
3. 「執行身分」選**我**；「誰可以存取」選 **任何人**。
4. 複製產生的網址（形如 `https://script.google.com/macros/s/AKfy.../exec`）。

### ⚠️ 別漏掉：擁有者要本人授權一次

部署完成**還不會動**。網頁應用程式以「你的身分」執行，所以 Google 需要你本人同意一次；
在你同意之前，任何請求都會拿到 403「需要存取權」，而且從外面看不出原因。

做法：在 Apps Script 編輯器按 **▷ 執行**（隨便執行哪個函式都可以）→ 選你的帳號 →
因為這支腳本沒有經過 Google 驗證，會看到警告，點 **進階 → 前往（不安全）** → **允許**。
要求的權限只有一項 `spreadsheets.currentonly`（只能寫這一份試算表），確認畫面上是這一項再按允許。

授權後用瀏覽器打開 `/exec` 網址，看到 `MYmate starter kit stats endpoint (alive)...` 就是好了。

## 步驟四：填進 bundle

編輯 `_stats.mjs`：

```js
export const STATS_ENDPOINT = "https://script.google.com/macros/s/AKfy.../exec";
```

同時確認 `BUNDLE_VERSION` 是當前版本。commit、發版即生效。

## 看數字：「統計」分頁

試算表裡有一個「統計」分頁，打開就看得懂，不必自己寫公式。版面由上到下：

| 區塊 | 內容 |
|---|---|
| 說明 | 「次數非人數」等前提，永遠放最上面 |
| 即時快照 | 安裝／卸載／淨留存、Mac／Windows／其他、首筆與最近事件、最近事件距今幾天 |
| 折線圖 | 累計安裝與累計淨留存的走勢 |
| 每日趨勢 | 近 60 天，**連續日期軸**，沒有事件的日子補 0 |
| 每週彙總 | 近 12 週（週一起算），事件稀疏時看這個 |
| 版本／平台分布 | 動態，冒出沒預期的值也看得到 |

### 要重建或調整

分頁是用 Apps Script 的 `setup()` 產生的（**可以重複執行**，會清空重建）。
在編輯器選 `setup` 按 ▷ 執行即可。要改觀察窗，動最上面那幾個常數：

```javascript
var DAILY_DAYS = 60;    // 每日趨勢的天數
var WEEKLY_WEEKS = 12;  // 每週彙總的週數
```

完整的 `setup()` 原始碼在專案內部開發紀錄（不放這裡，避免這份文件變成一大坨程式碼）。

### ⚠️ 兩個做趨勢很容易踩的坑

**一、不要用 `QUERY ... group by toDate()` 當趨勢來源。** 它只列出**有資料的日子**，
中間沒事件的日子會被整天跳過——畫出來是一條連續上升的線，實際上可能中間十天都沒人動。
要自己產生連續的日期軸，再用 `COUNTIFS` 逐日去數（`setup()` 就是這樣做的）。

**二、累計要算「全部歷史」，不要在視窗內累加。**
用 `COUNTIFS(時間欄,"<"&當日+1)`，這樣把視窗從 60 天改成 90 天時，累計數字不會整排跳動。

另外，`QUERY` 的 `toDate()` 輸出是日期序號，要對輸出範圍套 `yyyy-mm-dd` 格式，
否則會看到 `46245` 這種數字。

### 清除資料

`clearAllData()` 會清掉資料分頁的所有資料列、只留標題列，用來清測試資料。
**沒有備份，清掉就回不來**，執行前先確認。

## 幾件要知道的事

**這是「次數」不是「人數」。** 沒有任何識別碼，所以同一個人重裝三次會記三次，
也無法把某次卸載對應到某次安裝。這是刻意的取捨——換來「完全無法追蹤個人」。

**Repo 公開＝端點公開。** 任何人看得到網址，理論上可以灌水。
上面的驗證只擋掉格式不對的請求，擋不了刻意灌。
對「判斷要不要做訪談」這個用途來說可以接受；若日後發現異常暴增，看時間分布通常就能認出來。

**下載數另外看。** GitHub Releases 頁面有每個檔案的下載次數；
Insights → Traffic 有瀏覽與 clone 數（**只保留 14 天**，要長期追蹤得定期抓）。

**數字只是訊號。** 它能告訴你「該去問了」，不能告訴你「為什麼」。
真正要改什麼，還是得靠訪談與課程回饋。
